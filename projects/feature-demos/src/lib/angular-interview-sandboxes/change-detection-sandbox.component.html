The ngDoCheck & OnPush Interaction

A common misconception: "If a component is OnPush, ngDoCheck doesn't run."

This is FALSE. ngDoCheck executes on every single change detection cycle initiated by Angular, even if the component is configured with OnPush.

Why? Because ngDoCheck is designed exactly for this: to let developers perform their own custom dirty-checking when Angular's default reference-comparison checks are bypassed (such as object/array mutations).

If your custom check finds a change, you can instruct Angular to verify the view using one of two methods:

  • cdr.markForCheck(): Marks the component and all its ancestors as dirty. The actual template evaluation is deferred until the normal CD sweep reaches them.
  • cdr.detectChanges(): Forces Angular to immediately run change detection for this specific component subtree. Very fast, but can trigger errors if called out of order.
Senior Interview Prep: OnPush

Q: When does OnPush Change Detection actually run?

A: An OnPush component's template is checked ONLY when:
1. An @Input() memory reference changes (comparison uses ===).
2. An event listener (e.g., click) triggers inside the component or its children.
3. An AsyncPipe bound in the template receives a new stream emission.
4. ChangeDetectorRef APIs (markForCheck() / detectChanges()) are explicitly invoked.
5. A Signal read inside the template publishes a new value.
