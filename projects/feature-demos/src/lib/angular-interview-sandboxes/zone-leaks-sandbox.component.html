Zone.js Under the Hood

What is Zone.js?

Zone.js monkey-patches asynchronous browser APIs (such as Promise, setTimeout, addEventListener, and XMLHttpRequest) at application startup.

By interception, it informs Angular whenever an asynchronous task completes. Angular then triggers a change detection cycle starting from the root component to synchronize the state with the DOM.

Optimizing with runOutsideAngular:

Heavy background tasks (like animations, polling rates, WebGL renders, or canvas loops) that run repeatedly will trigger auto change detection constantly, causing UI lagging.

Wrapping these tasks in ngZone.runOutsideAngular(() => ...) bypasses the Zone.js wrapper. The callbacks execute silently. The UI is updated only when the developer calls cdr.detectChanges() or when code rejoins the Angular Zone.

Senior Interview Prep: Memory Leaks

Q: How do Observables cause memory leaks in Angular?

A: When a component subscribes to an infinite/long-lived Observable (e.g. global state, router events, or interval tickers), the Observable maintains a reference to the subscriber's callback function. If the component is destroyed but the subscription remains active, the JavaScript garbage collector cannot reclaim the component because the Observable still holds a reference to it. This leaks both the component class instances and its DOM elements.

Q: What are the three primary mitigation patterns?

A:
1. AsyncPipe: Automatically handles subscription and unsubscription of observables directly in the template.
2. takeUntil: Use an unsubscription Subject (e.g., destroy$) and pipe takeUntil(this.destroy$), firing it inside ngOnDestroy().
3. takeUntilDestroyed (Angular 16+): A developer-friendly injector-scoped operator that unsubscribes automatically when the current context (component/service) is destroyed.
