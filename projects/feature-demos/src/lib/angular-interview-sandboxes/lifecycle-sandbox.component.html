ngOnInit vs. ngAfterViewInit

A classic senior developer interview theme is the boundary between these two hooks:

  • ngOnInit runs once class properties and input bindings are resolved. It is the ideal place for data-fetching. However, the component's template elements are NOT rendered yet. Querying @ViewChild in ngOnInit returns undefined.
  • ngAfterViewInit runs when the component's HTML template and all of its child components have been fully created, rendered, and attached to the DOM. This is the first place you can safely manipulate the DOM or read element sizes.
⚠️ The "ExpressionChangedAfterItHasBeenCheckedError" Trap: Modifying a data-bound property inside ngAfterViewInit triggers this error because Angular has already checked the DOM output. If you must modify template state in ngAfterViewInit, defer it using setTimeout() or run it in a microtask.
Execution Sequence Reference
1 ngOnChanges Before ngOnInit; whenever input reference changes.
2 ngOnInit After inputs are first bound. Perfect for async queries.
3 ngDoCheck Runs during every check cycle for custom dirty checks.
4 ngAfterContentInit Once external projected content (ng-content) is ready.
5 ngAfterContentChecked Every check cycle after projected content completes.
6 ngAfterViewInit Once component template views and child views are bound.
7 ngAfterViewChecked Every check cycle after views have been validated.
8 ngOnDestroy Right before the component is unmounted. Unsubscribe now!
