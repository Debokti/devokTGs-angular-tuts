Why ::ng-deep is dangerous

Under the Hood (Emulated Scoping):

Angular encapsulates styles by appending generated attributes like _ngcontent-c12 to selectors. A rule like .themed-box is compiled to .themed-box[_ngcontent-c12].

When you use ::ng-deep, the compiler is instructed to strip the scoping attributes from that selector and everything downstream. If you write: 

::ng-deep .themed-box {{ '{' }} ... {{ '}' }}

It compiles to: 

.themed-box {{ '{' }} ... {{ '}' }}

This is a global selector. It will bleed out and style every element with class .themed-box in your entire SPA until the component style is destroyed (and even then, it can remain cached in style elements under certain conditions).

Senior Interview Prep: Styling

Q: How does Angular simulate style encapsulation in Emulated mode?

A: Angular adds a unique attribute (e.g., _nghost-c12) to the host element, and a matching attribute (e.g., _ngcontent-c12) to all elements inside the template. The compiler then rewrites the CSS selectors to require those attributes (e.g., .title becomes .title[_ngcontent-c12]).

Q: What is the recommended alternative to ::ng-deep?

A: Use CSS Custom Properties (Variables) on the child component that default to fallback values. The parent can then simply override the custom property values on the child's host selector. This maintains encapsulation boundaries and forms a clear, clean public styling API.
